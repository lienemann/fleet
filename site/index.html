Twenty-four Claude Code sessions.
One page that tells you which three need you.

fleet runs your Claude Code agents side by side, each in a jj workspace of its own. Permission prompts, questions and finished work come to an inbox, together with what Claude wrote just before asking. The rest of the output waits until you want to read it.

git clone https://github.com/lienemann/fleet && cd fleet && just install
What it needs, and the next two steps

You describe the work, and a director hands it out

  1. Tell a director what you want. Each repo you add is a project with a director of its own, which splits the work into tasks and writes a brief for each. A fleet director above them coordinates work that spans repos. Directors plan, but they cannot edit code.

  2. Each task gets a worker in its own jj workspace, so no two agents edit the same checkout. Tasks wait in the queue until a workspace is free.

  3. You answer what reaches the inbox and review each change hunk by hunk. When a worker revises its change, only the hunks it touched come back to you.

Every agent on one page

The board shows whose turn it is: one column per task state, with the permission prompts right on the cards. The rail on the left lists the agents and workspaces of each project, and the box at the bottom takes new work for the fleet director or a project's director.

The inbox has what waits on you

A permission prompt shows the command and the text Claude wrote just before asking. Risk tags mark network access, writes outside the workspace and code that runs. Questions, review requests and files of open points come here too, and you answer the points one by one.

The grid shows every session the way the CLI would

Each tile has the transcript, with subagents set apart from the agent that started them, plus the to-do list, the model, the permission mode and how full the context is. Its prompt knows slash commands and @ mentions and takes pasted images and files.

Review approves hunk by hunk

The diff follows the order of the agent's walkthrough and marks the hunks it leaves out. Click a line number and ask the agent about those lines; its answer appears right under them, like in a merge request. Hold questions instead, and Request changes sends them as one message. Fix a typo yourself and the edit lands in the commit that wrote the line.

The history puts all workspaces in one graph

The history view embeds jj orbit: the commits of every workspace, their bookmarks, and the operation log as a list of checkpoints you can step back through.

Close the tab, and the agents keep working

Nothing lives only in the browser

The daemon writes everything that happens to an event log. Close the tab, lose Wi-Fi or restart fleet, and every session resumes where it was.

Pods on the same page

Run the same daemon on a Coder pod and forward its port. Its agents show up next to your local ones, with the pod's name on them.

It tells you when to look

A desktop notification goes out when an agent needs you while fleet's tab is in the background. A banner warns when a disk with a workspace runs short of space.

Install

fleet runs on macOS and Linux. It needs:

  • Node 24, jj and just
  • Python 3, for the history view
  • Claude Code, logged in on the same machine
  1. git clone https://github.com/lienemann/fleet && cd fleet && just install

    Builds the web UI and puts the fleet command into ~/.local/bin.

  2. cd ~/your-repo && fleet init

    In the jj repo you want to work on: creates the workspaces ws1 to ws4 next to it and writes ~/.fleet/config.toml.

  3. fleet

    Starts the daemon and prints the link that logs your browser in. Press n for a new task.

The README covers the configuration, the keyboard shortcuts, and how Claude Code sessions you start yourself can work alongside fleet.
